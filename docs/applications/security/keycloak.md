# Keycloak

## What It Does

Keycloak is an open-source identity and access management (IAM) server that provides single sign-on (SSO), user federation, identity brokering, and social login for applications and services. It implements OpenID Connect (OIDC), OAuth 2.0, and SAML 2.0 protocols.

In this cluster, Keycloak runs as a single-replica Deployment in the `security` namespace, backed by a CloudNativePG-managed PostgreSQL database. The CNPG operator handles database provisioning, credential generation, and TLS encryption using cert-manager. Keycloak serves as the centralized authentication provider for cluster services. The admin console is accessible at `https://keycloak.k8s.local`.

## Why It's Here

Before Keycloak, each application in the stack managed its own authentication independently (or had no authentication at all). Keycloak provides:

- **Centralized identity management** — single user database for all applications
- **SSO across services** — log in once, access Grafana, ArgoCD, and other OIDC-capable services
- **Standard protocols** — OIDC/OAuth 2.0 integration without custom auth code per application
- **Self-service account management** — users can manage profiles, passwords, and 2FA via the Account Console
- **Realm isolation** — separate authentication domains for different use cases (e.g., `homelab` realm for cluster services)

## How It's Configured

### Installation

Keycloak is deployed via Kustomize manifests managed by ArgoCD:

```
argocd_applications/security/keycloak/
├── kustomization.yaml       # Resources, namespace, configMapGenerator for realm JSON
├── rbac.yaml                # ServiceAccount for Keycloak pods
├── database.yaml            # cert-manager Certificate + CNPG Cluster CR
├── homelab-realm.json       # Realm definition (consumed by configMapGenerator)
├── deployment.yaml          # Keycloak server (sync-wave 2), mounts realm ConfigMap
├── service.yaml             # ClusterIP service (port 8080) + headless discovery service
└── ingress.yaml             # Cilium Ingress with cert-manager TLS
```

### Sync Wave Ordering

Within the Keycloak Application, ArgoCD sync waves ensure resources are created in the right order:

| Wave | Resource | Purpose |
|------|----------|---------|
| 0 | `keycloak-db-server` Certificate | cert-manager issues TLS cert for PostgreSQL server |
| 1 | `keycloak-db` CNPG Cluster | Provisions PostgreSQL, generates `keycloak-db-app` Secret |
| 2 | `keycloak` Deployment | Keycloak server, reads database credentials from CNPG Secret |

The ArgoCD Application itself uses sync wave 2 (same as other core services like Thanos and Alertmanager), running after cert-manager and CloudNativePG operator (both wave 1) so that CRDs and issuers are available.

### CloudNativePG Database

PostgreSQL is managed by the CloudNativePG operator via a `Cluster` CRD in `database.yaml`. The operator handles:

- **Provisioning**: Creates a single PostgreSQL instance with the `keycloak` database and owner
- **Credentials**: Auto-generates the `keycloak-db-app` Secret containing `host`, `port`, `dbname`, `username`, `password`, `uri`, and `jdbc-uri`
- **Persistent storage**: Uses `rook-ceph-block` StorageClass (2Gi) for durable data (requires `ENABLE_ROOK=true`)
- **TLS**: Server certificate issued by cert-manager's `homelab-ca-issuer`, covering the `-rw`, `-ro`, and `-r` service DNS names
- **Metrics**: Prometheus annotations propagated to pods/services via `inheritedMetadata` for OTel Collector scraping (port 9187, path `/metrics`)
- **Services**: Automatically creates `keycloak-db-rw` (read-write), `keycloak-db-ro` (read-only), and `keycloak-db-r` (read) Services

### Secret Management

All database credentials are auto-generated by CloudNativePG — no manual Secret creation or init Jobs needed.

| Secret | Source | Keys | Purpose |
|--------|--------|------|---------|
| `keycloak-db-app` | CNPG operator | `host`, `port`, `dbname`, `username`, `password`, `uri`, `jdbc-uri` | Database connection credentials for Keycloak |
| `keycloak-db-server-tls` | cert-manager | `tls.crt`, `tls.key`, `ca.crt` | PostgreSQL server TLS certificate |

The initial admin user (`admin`/`admin`) is created by Keycloak's built-in bootstrap mechanism via `KC_BOOTSTRAP_ADMIN_USERNAME` and `KC_BOOTSTRAP_ADMIN_PASSWORD` environment variables. These are one-shot values — Keycloak ignores them once any admin user exists in the `master` realm. **Create a personal admin account with MFA via the Admin Console, then delete the default `admin` user.** The hardcoded values become dead code after that.

### Keycloak Server Configuration

The Keycloak container is configured via environment variables:

| Variable | Source | Purpose |
|----------|--------|---------|
| `KC_BOOTSTRAP_ADMIN_USERNAME` | Hardcoded `admin` | Initial admin username (first boot only) |
| `KC_BOOTSTRAP_ADMIN_PASSWORD` | Hardcoded `admin` | Initial admin password (first boot only — change via UI) |
| `KC_DB` | Hardcoded `postgres` | Database vendor |
| `KC_DB_URL_HOST` | `keycloak-db-app` Secret (`host`) | CNPG-managed PostgreSQL `-rw` Service |
| `KC_DB_URL_DATABASE` | `keycloak-db-app` Secret (`dbname`) | Database name (`keycloak`) |
| `KC_DB_USERNAME` | `keycloak-db-app` Secret (`username`) | Database user (`keycloak`) |
| `KC_DB_PASSWORD` | `keycloak-db-app` Secret (`password`) | Database password (auto-generated) |
| `KC_PROXY_HEADERS` | Hardcoded `xforwarded` | Trust proxy headers from Cilium Ingress |
| `KC_HTTP_ENABLED` | Hardcoded `true` | Serve HTTP (TLS terminated at Ingress) |
| `KC_HOSTNAME_STRICT` | Hardcoded `false` | Accept requests on any hostname (homelab flexibility) |
| `KC_HEALTH_ENABLED` | Hardcoded `true` | Enable health endpoints on port 9000 |

### Realm Import

The `homelab` realm is defined declaratively in `homelab-realm.json` and turned into a ConfigMap by Kustomize's `configMapGenerator`. The generator appends a content-hash suffix to the ConfigMap name (e.g., `keycloak-realm-homelab-g224fbb7m5`), and Kustomize automatically updates the Deployment's volume reference. When the realm JSON changes, the hash changes → new ConfigMap → Deployment rolls out → Keycloak re-reads the import directory.

The Deployment mounts the ConfigMap at `/opt/keycloak/data/import/` and starts Keycloak with the `--import-realm` flag.

Import behaviour:

- **First boot only** — Keycloak uses the `IGNORE_EXISTING` strategy (hardcoded, not configurable): the realm is created on first boot and skipped on subsequent restarts as long as a realm with the same name exists.
- **Realm-level only** — `--import-realm` creates the realm and its roles but does **not** overwrite existing users, clients, or settings. Manual changes made via the Admin Console are preserved.
- **Adding clients** — To declare OIDC clients as code, add entries to the `clients` array in `homelab-realm.json` and re-sync via ArgoCD. Keycloak will import new clients but leave existing ones untouched.
- **Breaking change to realm config** — If roles or realm settings need to change, delete the `homelab` realm via the Admin Console or `kcadm.sh delete realms/homelab`, then restart the pod. The import will recreate it with the updated JSON.

### Role Model

The homelab realm defines three hierarchical composite roles:

| Role | Inherits | Purpose |
|------|----------|---------|
| `cluster-admins` | `cluster-users` → `cluster-reviewers` | Full administrative access to cluster services |
| `cluster-users` | `cluster-reviewers` | Standard access to cluster services |
| `cluster-reviewers` | — | Read-only access to cluster services |

New users receive the `cluster-reviewers` role by default (least privilege). When configuring OIDC clients, map these realm roles to each application's authorization model (e.g., Grafana's `Admin` / `Editor` / `Viewer` org roles).

The homelab realm also ships with:

- Brute-force protection enabled (5 failures → lockout with 60 s incremental backoff, 900 s max)
- Login with email, remember-me enabled
- Self-registration disabled

### Ingress

Keycloak is accessible at `https://keycloak.k8s.local` via Cilium Ingress with cert-manager TLS:

- **TLS certificate**: Provisioned by `homelab-ca-issuer` ClusterIssuer, stored in `keycloak-tls` Secret
- **HTTPS enforcement**: `ingress.cilium.io/force-https: "enabled"` redirects HTTP to HTTPS
- **Backend**: Routes to the `keycloak` Service on port 8080

### Health Probes

Keycloak exposes health endpoints on management port 9000:

| Probe | Path | Purpose |
|-------|------|---------|
| Startup | `/health/started` | Waits for Keycloak to finish initializing (up to 5 min) |
| Readiness | `/health/ready` | Marks Pod as ready to receive traffic |
| Liveness | `/health/live` | Restarts Pod if Keycloak becomes unresponsive |

## Integration Points

| Direction | Target | Purpose |
|-----------|--------|---------|
| ← ArgoCD | Keycloak | Deploys and syncs Keycloak via Application CR |
| ← cert-manager | Keycloak Ingress | Provisions TLS certificate for `keycloak.k8s.local` |
| ← cert-manager | CNPG Cluster | Issues PostgreSQL server TLS certificate (`keycloak-db-server-tls`) |
| ← CloudNativePG | PostgreSQL | Manages database lifecycle, credentials, and Services |
| ← Rook-Ceph | CNPG PVC | Provides `rook-ceph-block` persistent storage for PostgreSQL data |
| → Cilium Ingress | External clients | Routes HTTPS traffic to Keycloak |
| → OTel Collector | PostgreSQL metrics | Scrapes CNPG instance metrics (port 9187) via prometheus annotations |
| → Grafana | OIDC provider | SSO via `grafana` client in homelab realm (role → org role mapping) |
| → ArgoCD | OIDC provider | SSO via `argocd` client in homelab realm (role → RBAC policy mapping) |

### OIDC Client Integration

OIDC clients are declared in `homelab-realm.json` and imported automatically with the realm. Both Grafana and ArgoCD are pre-configured:

| Client | Realm | Protocol Mappers | Role Mapping |
|--------|-------|------------------|--------------|
| `grafana` | homelab | `roles` (realm roles → `roles` claim) | `cluster-admins` → Admin, `cluster-users` → Editor, `cluster-reviewers` → Viewer |
| `argocd` | homelab | `roles` + `groups` (realm roles → both claims) | `cluster-admins` → `role:admin`, others → `role:readonly` |

**Grafana** reads the `roles` claim via `GF_AUTH_GENERIC_OAUTH_ROLE_ATTRIBUTE_PATH` (JMESPath expression) to map Keycloak roles to Grafana org roles. Configuration is in env vars in the Grafana Deployment.

**ArgoCD** OIDC config is managed by the `argocd-oidc` Application (sync wave 3, after Keycloak), which patches `argocd-cm` and `argocd-rbac-cm` ConfigMaps via `ServerSideApply`. This approach avoids modifying the day-0 bootstrap role — ArgoCD starts with local auth and gains OIDC after Keycloak is available.

Both services use `insecureSkipTLSVerify` / `tls_skip_verify_insecure` for backend OIDC calls since all endpoints share the same self-signed CA.

**To add a new OIDC client**: Add an entry to the `clients` array in `homelab-realm.json`, configure the service's OIDC settings, and sync via ArgoCD. If the homelab realm already exists, delete it first so `--import-realm` recreates it with the new client.

## Troubleshooting

```bash
# Check Keycloak pods are running
kubectl get pods -n security -l app=keycloak

# Check Keycloak logs
kubectl logs -n security -l app=keycloak -c keycloak --tail=50

# Check CNPG Cluster status
kubectl get cluster keycloak-db -n security
kubectl describe cluster keycloak-db -n security

# Check PostgreSQL pod managed by CNPG
kubectl get pods -n security -l cnpg.io/cluster=keycloak-db
kubectl logs -n security -l cnpg.io/cluster=keycloak-db --tail=50

# Verify CNPG-generated Secret exists
kubectl get secret keycloak-db-app -n security
kubectl get secret keycloak-db-app -n security -o jsonpath='{.data.host}' | base64 -d

# Check cert-manager Certificate for PostgreSQL TLS
kubectl get certificate keycloak-db-server -n security
kubectl describe certificate keycloak-db-server -n security


# Check Ingress and TLS
kubectl get ingress -n security
kubectl get certificate -n security

# Test health endpoint (from within cluster)
kubectl exec -n security -l app=keycloak -c keycloak -- curl -s http://localhost:9000/health/ready

# Check ArgoCD sync status
kubectl get application keycloak -n argocd
kubectl describe application keycloak -n argocd | tail -30
```

**Keycloak stuck in CrashLoopBackOff**: Check the CNPG Cluster is ready — Keycloak cannot start without a database connection. Verify the `keycloak-db-app` Secret exists (it's auto-generated by CNPG when the Cluster becomes healthy):

```bash
kubectl get cluster keycloak-db -n security -o jsonpath='{.status.phase}'
# Should show "Cluster in healthy state"
```

**CNPG Cluster stuck in provisioning**: Check that the `rook-ceph-block` StorageClass exists (`ENABLE_ROOK=true` required) and that the Rook cluster is healthy:

```bash
kubectl get storageclass rook-ceph-block
kubectl get cephcluster -n rook-ceph
```

**PostgreSQL TLS certificate not issued**: Verify cert-manager is running and the `homelab-ca-issuer` ClusterIssuer is Ready:

```bash
kubectl get clusterissuer homelab-ca-issuer
kubectl describe certificate keycloak-db-server -n security
```

**Realm roles not appearing after JSON change**: `--import-realm` uses `IGNORE_EXISTING` — it won't update a realm that already exists. Delete the realm and restart the pod:

```bash
# Authenticate with your admin account first, then:
kcadm.sh delete realms/homelab
kubectl rollout restart deployment/keycloak -n security
```

**Admin login not working**: The default bootstrap credentials (`admin`/`admin`) are one-shot — they only apply on first boot when no admin user exists. If you created a personal admin and deleted the default `admin` user, the hardcoded env vars are dead code. To fully reset, delete the CNPG Cluster and let ArgoCD recreate it:

```bash
kubectl delete cluster keycloak-db -n security
# ArgoCD will recreate the Cluster, re-bootstrap the database, and Keycloak will create a new admin user
```

**TLS certificate not provisioned for Ingress**: Verify cert-manager is running and the `homelab-ca-issuer` ClusterIssuer is Ready. Check certificate status:

```bash
kubectl describe certificate keycloak-tls -n security
kubectl get certificaterequest -n security
```
