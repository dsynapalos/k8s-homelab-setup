# Architecture Diagrams

This directory contains all architecture diagrams for the cluster-setup project. Each diagram is a self-contained SVG file that can be:

- **Viewed directly** on GitHub/GitLab (rendered inline in Markdown)
- **Opened in draw.io** for visual editing (the embedded data round-trips cleanly)
- **Edited as XML** by AI agents or by hand (mxGraph XML is stored in a `<metadata>` block inside the SVG)

| Diagram | Description |
|---------|-------------|
| [ansible-pipeline.svg](ansible-pipeline.svg) | The 15-play Ansible pipeline — shows which Python entry points trigger which playbooks, the execution order, and where artifacts are produced |
| [gitops-app-of-apps.svg](gitops-app-of-apps.svg) | ArgoCD app-of-apps hierarchy — parent app, platform tier (sync waves 1–3), services tier (wave 4), and individual Application CRs |

## How It Works

Each SVG file contains three representations of the same diagram:

1. **Rendered SVG elements** — the shapes, lines, and text you see when viewing the file. Generated by `library/scripts/export-diagrams.py`.
2. **Readable mxGraph XML** — stored in a `<metadata id="drawio-source">` block inside the SVG. This is the editable source.
3. **Base64-encoded content** — in the `content` attribute on the root `<svg>` element. This is what draw.io reads when you open the file.

There are **no separate `.drawio` files** — the SVG is the single source of truth.

## Editing Diagrams

### Option 1: draw.io (visual)

1. Open the SVG directly in [draw.io](https://app.diagrams.net/) (File → Open).
2. Make your changes visually.
3. Save — draw.io updates the SVG in place.
4. Run the rebuild script to re-sync the rendered layer:
   ```bash
   python3 library/scripts/export-diagrams.py --rebuild docs/diagrams/<name>.svg
   ```

### Option 2: Edit the XML directly

1. Open the SVG in a text editor.
2. Find the `<metadata id="drawio-source"><![CDATA[...]]>` block.
3. Edit the mxGraph XML (add/move/remove `<mxCell>` elements).
4. Run:
   ```bash
   python3 library/scripts/export-diagrams.py --rebuild docs/diagrams/<name>.svg
   ```

### Creating a new diagram

1. Create an SVG with the skeleton template (see [SKILL.md](../../.github/skills/render-drawio-diagram/SKILL.md) for the template).
2. Add your mxGraph XML inside the CDATA block.
3. Run `--rebuild` to generate the visual layer.
4. Link the diagram from the relevant documentation page using `![alt](../diagrams/<name>.svg)`.

## Rebuild Script

The renderer is a pure-Python script with no external dependencies:

```bash
# Rebuild all diagrams
python3 library/scripts/export-diagrams.py --rebuild

# Rebuild a single diagram
python3 library/scripts/export-diagrams.py --rebuild docs/diagrams/storage-architecture.svg

# Remove all rendered SVGs (leaves metadata intact)
python3 library/scripts/export-diagrams.py --clean
```

## Style Conventions

Diagrams follow a consistent visual language:

| Element | Color | Shape |
|---------|-------|-------|
| Containers (clusters, namespaces) | Blue (`#dae8fc`) | Swimlane with title bar |
| Services / Pods | Green (`#d5e8d4`) | Rounded rectangle |
| External systems | Yellow (`#fff2cc`) | Rectangle |
| Data stores | Purple (`#e1d5e7`) | Cylinder |
| Entry points / Load balancers | Red (`#f8cecc`) | Rounded rectangle |
| Config labels | Grey (`#f5f5f5`) | Small rounded rectangle |

All connectors use orthogonal (right-angle) routing. Layout flows left-to-right with entry points on the left and data stores on the right.
